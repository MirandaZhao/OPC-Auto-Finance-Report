# 设计文档：系统如何运作、为何如此设计

## 总体架构

```
CSV 导入 / 内置样例数据
        │
        ▼
┌─────────────────────┐
│  计算引擎 ENGINE     │  纯函数、零 DOM 依赖，可独立测试
│  · 逐月数据模型 rows │  每行：收入明细、成本明细、回款、应收、现金
│  · metrics(sel)     │  按所选月份聚合出 20+ 指标
│  · score(m)         │  五维评分规则引擎
│  · narrative / advice│ 结论句与建议动作
│  · forecast(opts)   │  6 个月现金推演
└─────────────────────┘
        │
        ▼
  渲染层（Chart.js 10 张图 + 手绘 SVG 桑基图 + 三张报表）
```

## 关键设计决策

**为什么单文件？**
目标用户是小微企业主和代账会计，不是开发者。单文件意味着：双击就能打开、微信里能直接转发、不需要任何安装步骤。代价是不利于多人协作，这个取舍是故意的。

**为什么计算引擎和渲染分离？**
引擎（`ENGINE`）是纯数据进、数据出，不碰 DOM。这样它可以在 Node 里直接跑断言测试（`docs/engine.test.js`），也方便未来拆出去做后端或小程序。

**为什么评分用规则引擎而不是加权平均？**
五维评分的每一维都有明确的业务阈值（如 DSO ≤45 天算健康、现金可支撑 ≥3 个月算安全），这些阈值来自常见的小微企业财务经验。规则引擎让每个分级都能解释——界面上每一项都附带一句「为什么是这个级别」的大白话。

**为什么桑基图手写 SVG 而不用图表库？**
Chart.js 4.x 不支持桑基图。手绘 SVG 约 20 行，且能保证流入流出严格守恒（左侧收入明细合计 = 右侧成本明细合计 + 净利润）。

**为什么推演从「剩余回款表」出发而不是简单按比例？**
应收账款是历史订单逐月回款的累积。推演时把每笔历史收入的剩余回款计划平移进未来月份，再叠加新订单的回款表，这样「回款延后 60 天」才有真实含义——不是把现金整体打折，而是把现金曲线的形状往后推。

## 数据流与状态

- 全局状态只有两个：`ENGINE.rows`（当月数据集）和 `state.sel`（所选月份索引）
- 任何筛选变化都触发全量重渲染（`render()`），数据量 ≤ 数百行，无性能问题
- 用户筛选偏好持久化在 `localStorage`（键 `dash-sel`）

## CSV 导入契约

模板列名（17 列，顺序固定）：

```
月份(YYYY-MM), 标准件销售, 定制件销售, 来料加工服务, 配件与其他,
原材料采购, 生产人工, 物流运输, 销售推广, 水电燃气, 税费,
厂房租金, 管理人员工资, 设备折旧, 贷款利息,
客户回款, 期末应收账款, 期末账上现金
```

- 金额单位：万元；至少 2 个月数据
- 导入后逐行校验：月份格式、列数、数值合法性；失败时给出精确到行号的错误信息
- 收入总额 = 四项收入明细之和（自动计算，不单独提供列）

# 指标口径

金额单位统一为万元；所有指标按"所选月份"汇总计算。

| 指标          | 计算方法                                    | 阈值（健康 / 关注 / 风险）      | 为什么这么定                              |
| ----------- | --------------------------------------- | --------------------- | ----------------------------------- |
| 净利润率        | 净利润 ÷ 收入                                | ≥8% / 3–8% / <3%      | 制造类小微企业净利率常见 5–12%，低于 3% 一次原材料涨价就会亏 |
| 毛利率         | （收入 − 原材料 − 生产人工 − 物流 − 水电）÷ 收入         | 辅助指标，<40% 触发成本建议      | 毛利率是定价与采购议价能力的直接体现                  |
| 现金可支撑月数     | 期末现金 ÷ 月均刚性支出（不含折旧，含还贷）                 | ≥3 / 1.5–3 / <1.5     | 3 个月是大额回款延迟时最起码的缓冲                  |
| 回款周期 DSO（天） | 期末应收 ÷ 最近 3 个月收入 × 90                   | ≤45 / 45–75 / >75     | 国内 B2B 常见账期 30–45 天                 |
| 逾期占比        | 账龄 >90 天应收 ÷ 期末应收                       | <12% / <25% / ≥25%    | 超过 90 天的应收坏账风险显著上升                  |
| 稳定支出        | 房租 + 管理工资 + 折旧 + 利息                     | —                     | 没有生意也要付                             |
| 弹性支出        | 原材料 + 生产人工 + 物流 + 推广 + 水电 + 税费          | —                     | 跟着订单走，可压缩                           |
| 毛利覆盖倍数      | 毛利 ÷ 稳定支出                               | ≥1.6 / 1.2–1.6 / <1.2 | 淡季收入常下降 30–40%，1.6 倍才能扛住            |
| 成长性         | 所选期间收入与上年同期比；无同期数据时与紧邻上一段比              | ≥10% / 0–10% / <0     | 与通胀和行业增速大致持平                        |
| 健康评分        | 五维加权：盈利 25%、现金 25%、回款 20%、成本 15%、成长 15% | ≥70 / 50–69 / <50     | 现金与盈利并重，各占四分之一                      |

## 调整阈值

阈值集中在 `index.html` 的 `ENGINE.score()` 函数，每个维度一段。修改后：

1. 同步更新本文件和页面「数据管理 → 指标口径」表格；
2. 运行 `node --test tests/engine.test.js`，确认极端输入仍在 0–100 范围内。

## 行业适配提示

- 贸易 / 零售：毛利率阈值应下调（常见 15–25%），DSO 阈值可收紧。
- 服务业：原材料项可置零，稳定支出中人工占比更高，毛利覆盖倍数阈值可放宽到 1.3。
