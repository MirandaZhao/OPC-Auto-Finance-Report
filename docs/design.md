# 系统设计

## 1. 目标与取舍

- **目标**：让没有财务背景的小微企业老板，在 3 分钟内看懂本月经营状况和最该做的一件事。
- **取舍**：为了"打开就能用、数据不出本机"，放弃了后端与数据库，整个应用是一个 HTML 文件；为了"每条结论都能解释"，评分用透明的规则而不是机器学习模型。

## 2. 架构

```
index.html
├── <style>            设计系统：CSS 变量（浅色 / 深色）、版式、组件
├── <script> ENGINE    计算引擎（无 DOM 依赖，可在 Node 中单独测试）
│    ├── 样例数据生成    24 个月虚构数据，固定随机种子，结果可复现
│    ├── metrics(sel)   按所选月份聚合指标
│    ├── score(m)       五维评分与等级
│    ├── narrative()    一句话总结与关注点
│    ├── advice()       可执行建议（动作 + 影响估算）
│    ├── forecast()     未来 6 个月现金推演
│    ├── quality()      数据质量检查
│    └── setRows()      用导入数据替换样例数据
└── <script> 渲染层     筛选器、七个页面的渲染、Chart.js 图表、桑基图（SVG）、CSV 导入
```

## 3. 数据模型

每个月一条记录（`rows[i]`），核心字段：

| 字段 | 含义 | 来源 |
|---|---|---|
| `rev`, `revMix[4]` | 收入总额与四类收入 | 导入 / 生成 |
| `costs{10}` | 十项成本费用（6 项弹性 + 4 项稳定） | 导入 / 生成 |
| `collections` | 当月客户回款 | 导入 / 按账期分布生成 |
| `arEnd`, `cashEnd` | 期末应收、期末现金 | 导入 / 滚算 |
| `aging[4]` | 账龄 ≤30 / 31–60 / 61–90 / >90 天 | 按未回款切片估算 |
| `stableCost`, `flexCost` | 稳定支出、弹性支出 | 由 `costs` 分类求和 |
| `dso` | 回款周期（天） | 期末应收 ÷ 近 3 月收入 × 90 |

**稳定 / 弹性划分**是本项目最重要的设计决定之一：房租、管理工资、折旧、利息不管有没有生意都要付，其余跟着订单走。"毛利能覆盖稳定支出几倍"直接决定淡季会不会亏损。

## 4. 评分规则

五个维度各映射到 0–100 分，再加权（盈利 25%、现金 25%、回款 20%、成本 15%、成长 15%）：

| 维度 | 输入 | 分数公式 | 健康 / 关注 / 风险 |
|---|---|---|---|
| 盈利能力 | 净利率 | 30 + 净利率 × 4.7 | ≥8% / 3–8% / <3% |
| 现金安全 | 可支撑月数 | 月数 × 22 | ≥3 / 1.5–3 / <1.5 |
| 回款效率 | DSO、逾期占比 | 120 − DSO × 1.05 − 逾期% × 0.8 | DSO≤45 且逾期<12% / DSO≤75 且逾期<25% / 其他 |
| 成本控制 | 毛利覆盖倍数 | 倍数 × 32 | ≥1.6 / 1.2–1.6 / <1.2 |
| 成长性 | 收入同比 | 50 + 增速 × 3.2 | ≥10% / 0–10% / <0 |


## 5. 建议生成

`advice()` 按维度状态触发，每条建议包含：等级、标题、正文（具体到找谁、做什么、什么时限）、影响（用当前数字算出来的预计效果）。例如回款效率不健康时，建议由老板本周联系应收占比最大的客户约定分期回款，并给出"收回一半逾期款后可支撑月数提高到 X 个月"。

建议按等级（风险 > 关注）排序，保证老板先看到最要紧的。

## 6. 沙盘推演

`forecast({revChange, collectDelay, flexCut})`：

1. 用最近 3 个月去季节化收入作为基准，乘以月度季节系数和收入变化率，得未来 6 个月收入。
2. 每笔收入（历史的和未来的）按账期分布表拆成未来各月的回款；`collectDelay` 按 30 天为单位整体平移分布表。
3. 弹性支出按收入比例计算并乘以 `(1 − flexCut)`；稳定支出取最后一个月（不含折旧）；加每月还本。
4. 现金逐月滚算；安全线 = 最近 6 个月平均刚性支出 × 3。

推演是**规则式外推**，不含增长预测模型，只回答"如果这三件事发生，账上会怎样"。

## 7. 渲染层要点

- Chart.js 图表统一经 `mk(id, cfg)` 创建，重渲染前销毁旧实例，避免内存泄漏。
- 桑基图手写 SVG，左右两侧总额相等（测试项之一）。
- 颜色全部取自 CSS 变量，切换深色模式后重绘即可。
- `IntersectionObserver` 驱动顶部导航高亮；`scroll-padding-top` 处理粘性顶栏遮挡。

## 8. 已知局限

- 导入 CSV 后账龄按固定比例（60/20/12/8）估算，不是真实账龄。
- 导入模式下资产负债表中固定资产、贷款为 0（模板不采集这两项）。
- 客户回款明细在导入模式下仍使用样例客户名单。
- 财务软件接口、手工录入未实现。
